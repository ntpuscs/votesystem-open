# 議會表決系統：安裝與使用說明

現場即時表決系統（各校通用版）

> 本系統由國立臺北大學三峽校區學生議會提供並協助架設。

## 檔案內容

| 檔案 | 用途 |
|---|---|
| `Code.gs` | 後端程式，貼到 Google 試算表的 Apps Script |
| `index.html` | 前端網頁，上傳到 GitHub Pages |
| `議員名單範本.csv` | 「議員」工作表的格式範例，可直接匯入 |

同一個網址有三個畫面：

| 網址 | 畫面 | 誰用 |
|---|---|---|
| `https://你的網址/` | 議員手機投票 | 議員 |
| `https://你的網址/#/admin` | 秘書處控制台 | 秘書處 |
| `https://你的網址/#/screen` | 投影大螢幕（按 F 或連點兩下切換全螢幕） | 投影電腦 |

## 一、建立 Google 試算表

1. 新增一份 Google 試算表，例如命名為「議會表決系統」。
2. 點選「擴充功能 → Apps Script」。
3. 刪掉預設內容，貼上 `Code.gs` 的全部內容，然後儲存。
4. 上方函式選單選 `setup`，按「執行」。第一次執行會要求授權，請依指示允許。
5. 回到試算表，會出現四個工作表：

| 工作表 | 內容 | 誰維護 |
|---|---|---|
| 議員 | 帳號、密碼、選區（選填）、姓名、排序 | 秘書處填寫 |
| 設定 | 秘書處密碼、會議名稱 | 秘書處填寫 |
| 表決紀錄 | 每次表決一列，附防竄改簽章（自動寫入，僅擁有者可編輯） | 系統 |
| 記名明細 | 記名表決時每位議員的投票，附簽章（自動寫入，僅擁有者可編輯） | 系統 |
| 操作紀錄 | 秘書處每一次登入、勾選出席、開始／延長／截止表決的時間與內容，附簽章 | 系統 |

### 填寫「議員」工作表

| 帳號 | 密碼 | 選區（選填） | 姓名 | 排序 |
|---|---|---|---|---|
| d01 | （自訂） | 第一選區 | 王小明 | 1 |

- **帳號**：英數字，不可重複。
- **密碼**：由秘書處設定後個別通知議員。
- **選區**：選填。有填就顯示在大螢幕名牌上方及控制台名單；不填只顯示姓名（名字會自動放大）。
- **排序**：大螢幕上的顯示順序，由左到右、由上到下。
- 也可以用「檔案 → 匯入」把 `議員名單範本.csv` 匯入到這個工作表。

### 填寫「設定」工作表

| 項目 | 值 |
|---|---|
| 秘書處密碼 | 秘書處登入控制台用的密碼，**至少 8 個字元**；未修改預設值時系統會拒絕登入 |
| 會議名稱 | 例如「第○屆第○次大會」，會顯示在每個畫面上 |

> 修改名單或設定後，請在控制台按「重新讀取名單」，否則最多 2 分鐘後才會生效。

## 二、部署後端

1. 在 Apps Script 右上角點「部署 → 新增部署作業」。
2. 類型選「網頁應用程式」。
3. 「執行身分」選 **我**；「誰可以存取」選 **所有人**。
4. 按「部署」，複製「網頁應用程式網址」（結尾是 `/exec`）。

> 之後如果修改 `Code.gs`，要用「部署 → 管理部署作業 → 編輯 → 版本：新版本」重新部署，網址不會變。

## 三、設定前端並上傳

1. 用文字編輯器打開 `index.html`，找到 `<script>` 下方的「設定」區塊，修改這兩行：
   ```js
   const ORG = '（您的組織）';   // 改成貴會名稱，例如「○○大學學生議會」
   const API_URL = 'https://script.google.com/macros/s/請貼上部署網址/exec';   // 改成剛才複製的部署網址
   ```
   組織名稱會顯示在每個畫面的頂端與瀏覽器分頁標題。
   （畫面右下角的「本系統由國立臺北大學三峽校區學生議會提供並協助架設」為提供者標示，請保留。）
2. 把 `index.html` 上傳到任何靜態網站空間即可，例如 GitHub Pages（建立儲存庫 → 上傳 `index.html` → Settings → Pages → 選擇分支後儲存）。

## 開會流程

**會前**
1. 秘書處確認「設定」裡的會議名稱已更新。
2. 秘書處打開 `#/admin`，按「清除全部簽到（新會議）」，把上次會議的簽到清掉。
3. 投影電腦打開 `#/screen`，按 F 進入全螢幕。

**簽到（確認出席）**
- 議員用手機打開網址，輸入帳號密碼登入。登入後手機顯示「待秘書處確認出席」。
- 秘書處在控制台左側名單看到「已登入，待確認出席」的議員，**確認本人在場後勾選「出席」**；議員手機會改為「已確認出席」。
- 只有勾選出席的議員可以投票，避免未到場者遠端登入投票。
- 議員中途離席，取消勾選即可；忘記帶手機或無法登入者，一樣可以先勾選出席（但仍需登入才能投票）。

**表決**
1. 主席宣告表決事項、方式和門檻後，秘書處填寫「建立表決」：
   - 議案編號：選填，依貴會的編號格式輸入，系統原樣顯示與記錄；臨時動議可以留空。
   - 表決事項、案別、記名或不記名、門檻、時限。
2. 按「開始表決」，議員手機會在 2 秒內出現投票按鈕。
3. 議員點選選項後，要再按「確認送出」才算投票；送出後無法更改。
4. 倒數結束時系統自動截止；秘書處也可以按「延長 30 秒」或「立即截止」。
5. 截止後，大螢幕顯示結果，同時寫入 Google Sheet。
6. 按「複製結果文字（議事錄用）」，可以直接貼進會議紀錄。
7. 按「建立下一個表決」，繼續下一案。

## 規則說明

| 項目 | 規則 |
|---|---|
| 選項 | 一般議案：贊成／反對／棄權；人事案：同意／不同意 |
| 誰能投票 | **按下「開始表決」當下，經秘書處勾選「出席」**的議員。僅登入但未經確認者不能投票；表決中才勾選的，從下一案起才能投。 |
| 送出 | 點選選項後須按「確認送出」；送出後不可更改。未按確認送出就截止，視為未投票。 |
| 席次 | 大螢幕自適應 10–50 席：自動量測畫面大小，選擇字體最大的欄數排法（例：10 席 5×2、18 席 5×4、30 席 8×4、50 席 10×5），每格顯示姓名，有填選區時一併顯示。視窗大小改變時自動重排。 |
| 顏色 | 贊成（同意）綠色、反對（不同意）紅色、棄權黃色；未投票為黑色，未出席為淺灰色。 |
| 主席 | 不投票。主席如果也在「議員」工作表裡，開會時請把他設為離席，或直接不列入名單。 |
| 可否同數 | 顯示「可否同數，由主席裁決」，由主席口頭宣告 |
| 同時登入 | 同一帳號在新裝置登入後，舊裝置會被登出，避免代投 |

### 可決門檻

| 門檻 | 通過條件 | 例：出席 16 人、全體 18 人 |
|---|---|---|
| 簡單多數決 | 贊成多於反對，棄權不計 | 贊成 > 反對 |
| 出席過半數 | 贊成 ≥ 出席人數的一半再加一（無條件捨去） | 贊成 ≥ 9 |
| 出席三分之二 | 贊成 ≥ 出席人數 × 2/3（無條件進位） | 贊成 ≥ 11 |
| 全體過半數 | 贊成 ≥ 全體人數的一半再加一 | 贊成 ≥ 10 |
| 全體三分之二 | 贊成 ≥ 全體人數 × 2/3（無條件進位） | 贊成 ≥ 12 |

「出席人數」是開始表決當下經秘書處確認出席的人數；「全體人數」是「議員」工作表裡的總人數。如果議事規則的算法不同，請修改 `Code.gs` 裡的 `need_()` 函式，以及 `index.html` 裡的 `needTextFor()` 函式。

### 不記名表決

- 表決進行中，系統只在後台暫存「誰投了什麼」，用來防止重複投票和讓議員改票。
- **截止的同時就刪除個別投票**，試算表也只記錄總票數。
- 這些暫存資料存在 Apps Script 的指令碼屬性中，擁有 Apps Script 編輯權限的人在表決進行中理論上看得到。因此請只讓秘書處的負責人擁有試算表與 Apps Script 的編輯權限。

## 常見問題

**議員手機顯示「登入已失效」**
同一帳號在另一台裝置登入過，或是秘書處按了「清除全部簽到」。重新登入即可。

**畫面更新有延遲**
各畫面每 1.5～2 秒向伺服器更新一次，正常延遲大約 2～3 秒。倒數時間以伺服器時間為準，各裝置的倒數會一致。

**表決卡住，無法建立新表決**
在 Apps Script 編輯器執行 `resetAllState`。這會清除簽到、登入和目前的表決，不會影響試算表裡的紀錄。

**名單改了，畫面卻沒變**
在控制台按「重新讀取名單」。

## 安全性

### 2026/11/15 安全性更新（請務必更新）

舊版有一個嚴重漏洞：**不需要秘書處密碼**，只要在送出的資料裡把秘書處憑證填成特定字串（例如 `constructor`），就能通過權限檢查，進而勾選出席、開始與截止表決，寫入偽造的表決結果。本版已修正，並加強以下防護：

| 項目 | 說明 |
|---|---|
| 憑證檢查 | 只接受系統發出、格式正確的登入憑證，特殊字串一律拒絕 |
| 防猜密碼 | 同一帳號（含秘書處）連續輸錯 8 次，鎖定 10 分鐘；已登入的裝置不受影響 |
| 預設密碼 | 秘書處密碼少於 8 字元或仍是範本預設值時拒絕登入；議員密碼為「請改成密碼」「請自訂」或空白的帳號無法登入 |
| 網址不帶密碼 | 只有投影畫面資料可以用網址讀取；登入與所有操作一律以 POST 傳送，密碼不會出現在網址或瀏覽紀錄 |
| 防竄改簽章 | 表決紀錄、記名明細、操作紀錄每一列都附有串連的 HMAC-SHA256 簽章。事後有人直接修改試算表的任何一格、刪除或插入列，控制台「表決紀錄」上方會以紅框標出是哪一列 |
| 操作紀錄 | 秘書處的每個動作都留下時間與工作階段代碼，可事後核對 |
| 工作表保護 | 執行 `setup()` 時，三張紀錄表會設為「僅擁有者可編輯」 |

**從舊版更新的步驟**
1. 用新的 `Code.gs` 取代舊程式碼，**再執行一次 `setup()`**：會補上「操作紀錄」工作表、建立簽章金鑰並保護紀錄表，不會動到既有資料。
2. 「部署 → 管理部署作業 → 編輯 → 版本：新版本」重新部署。
3. 更新 `index.html`。
4. 確認「設定」工作表的秘書處密碼至少 8 個字元；**若擔心舊密碼外流，順便更換**。
5. 檢查「表決紀錄」中是否有你們沒有進行過的表決。舊紀錄沒有簽章，控制台會標示為「啟用簽章前的舊紀錄」。

### 這套系統防得住什麼、防不住什麼

- **防得住**：不知道密碼的外人（包括看得到網址、看得懂前端程式碼的人）、暴力猜密碼、只有試算表編輯權限的人偷改紀錄（會被簽章驗出）。
- **防不住**：能編輯 Apps Script 的人。他可以讀取簽章金鑰、修改程式本身。請記得：**有試算表編輯權限的人，也能打開該試算表的 Apps Script**。

所以請務必：
- 試算表與 Apps Script 由**一個議會專用的 Google 帳號**擁有，**不要分享編輯權限**給其他人。秘書處只需要使用網頁控制台，不需要碰試算表。
- **不要把這份試算表「發布到網路」，也不要開「知道連結的人皆可檢視」**，因為「議員」「設定」工作表裡有明文密碼。若議案查詢網站需要發布試算表，請使用另一份檔案。
- 想更嚴格時，可以把 Apps Script 改成獨立專案、以試算表 ID 開啟，讓有試算表權限的人碰不到程式與金鑰。
- 在 Apps Script 編輯器執行 `verifyRecords()` 也可以手動檢查紀錄，結果會顯示在執行紀錄中。
- 注意：連續輸錯密碼的鎖定也可能被人故意觸發（例如在開會時亂猜秘書處密碼）。開會前先登入控制台即可，已登入的裝置不受鎖定影響。
